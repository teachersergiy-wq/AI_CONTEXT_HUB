# Навчальна студія — DECISIONS

## 2026-10-18 — Рішення власника для MVP (D1–D7)
- **D1 (формат — active):** логін учня — 3–4 латинські літери; пароль — 1 літера + 3 цифри, видаються системою. **Умова безпеки (proposed, чекає схвалення):** простір таких паролів малий (близько 26 тис. при одному регістрі). За документацією Supabase ліміт на токен-ендпоінт — 150 запитів за 5 хв на IP, тож підбір пароля одного акаунта можливий за години. Пропозиція: вхід учня лише через серверну функцію з лічильником невдалих спроб і тимчасовим блокуванням (учитель може скинути пароль); внутрішній пароль Auth довший за пароль учня (серверний секрет «перець»), щоб прямий підбір через Auth був неможливий. Чи приймає Auth пароль із 4 символів, не перевірено: документація Supabase радить ≥ 8, нижню межу налаштування треба перевірити на локальному Supabase.
- **D2 (active):** підтримуються типи питань: `true_false`, `single_choice` (4–5 варіантів), `multiple_choice`, `ordering` (послідовність), `matching` (відповідність), `numeric`, `short_answer` (текстова відповідь). VERIFIED: типів `ordering` і `matching` у БД ще немає (enum `question_type`), потрібна окрема міграція. **Proposed:** окремий банк питань для повторного використання — після MVP, якщо власник не вкаже інакше.
- **D3 (active):** публікація тесту лише через серверну функцію, яка перевіряє ключі відповіді; прямі зміни статусу на `published` з клієнта заборонити.
- **D4 (active):** у MVP учень належить одному класу; кілька класів — після MVP.
- **D5 (active):** режим `graded` — без підказок до завершення; режим `practice` — показ правильності після кожної відповіді.
- **D6 (active):** хостинг — спочатку перевірити GitHub Pages разом з Auth; до перевірки не обіцяти.
- **D7 (active — запрошення):** реєстрація вчителів лише за запрошенням. **Механізм (proposed):** публічну реєстрацію вимкнути; акаунти вчителів створює власник у панелі Supabase без листів (за документацією, вбудована пошта — 2 листи на годину); `provision-teacher` створює профіль лише для дозволених акаунтів. Те, що вимкнення реєстрації не заважає створенню користувачів адміністратором, потрібно перевірити.

## 2026-10-18 — Права доступу й версії міграцій (запропоновано, чекає схвалення власника)
**Пропозиція:** (1) версії файлів у `supabase/migrations/` дорівнюють версіям, застосованим у проєкті; (2) права `anon`/`authenticated` на таблиці `public` видаються явно й мінімально, без успадкованих за замовчуванням; (3) спільні конфігурації множення змінюються лише міграцією або серверною функцією, а не клієнтом вчителя; (4) шаблон створюється лише як `draft`.
**Реалізація:** гілка `claude/harden-grants-and-align-migrations` у `teachersergiy-wq/multiplication-practice`; міграція не застосована.
**Рішення власника (D3):** публікація тесту (`draft` → `published`) виконується лише серверною функцією, яка перевіряє наявність ключів відповіді для кожного питання. Зараз клієнт може виставити `published` напряму; це має закрити Grok у межах завдань хвилі 2.
**Статус:** proposed.
