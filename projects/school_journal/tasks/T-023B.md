# T-023B — RLS verification (owner, anon, non-owner)

- **Owner:** Grok (Claude re-checks)
- **Status:** PLANNED
- **Depends on:** T-023A applied

## Goal
Prove, with recorded results, that only the owner can read or change data today.

## Checks (run in transactions that are rolled back; synthetic data only)
1. Owner: can read and write journals, lessons, lesson records, behaviour links, exits and assessments, and can call `save_lesson_record`.
2. `anon`: denied on every table, the view and every function.
3. An authenticated user who is not the owner and has no profile (simulated JWT claims with a random uuid): sees zero rows and cannot insert, update or delete anything.
4. No user can change `profiles.role`.
5. `v_lesson_window` returns rows for the owner and nothing for the others (needs the demo data of T-024).

## Deferred to T-050
Isolation between two teachers. It needs a second test account with a fictional address, so it is done when several teachers are enabled.

## Done when
Results are in `docs/RLS_TEST_REPORT.md` (app repo) with the SQL used. Claude re-runs a sample of the checks read-only and gives the verdict.
