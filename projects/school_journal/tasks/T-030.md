## Goal
A mobile-first installable web app that shows the journal flow on fictional data.

## Step 1 — stack note (in the same PR, `docs/STACK.md`, up to one page)
Propose the stack and why. Constraints: free tools only; static build; no paid service; hosting is not chosen yet (T-006), so do not depend on one host; `supabase-js` for the data layer later.

## Step 2 — skeleton
- Screens: sign-in, my journals (subject + class), lesson dates of a journal, lesson window (students on the left, lesson characteristics on the right, read-only for now).
- Language: Ukrainian. Large touch targets, usable on a phone.
- Sign-in with email and password only. No sign-up screen and no password-reset flow (single user; signup is disabled).
- Data layer: a repository interface with an in-memory mock implementation (fictional data) and a Supabase implementation stub; the choice is made by configuration.
- PWA: manifest, service worker for the app shell only (installable). No offline data writes in v1.
- Configuration through environment variables; add `.env.example` with placeholder names only. Never commit real keys or URLs of private values.
- `README.md` with how to install, run, build and test.

## Rule for the data layer
The app never filters data by teacher or by user role. Access is limited only by the database (RLS). This keeps the system ready for several teachers.

## Characteristics to show in the lesson window (from DATA_CONTRACT.md)
Absence `н`; homework (done / partial / not done); notebook; textbook; not taking notes; board (a grade, or refused); behaviour marks (several); exits with reason (toilet / phone / other, several); late minutes; assessments. No ГР1–ГР3 columns.

## Done when

- `README.md` and `docs/STACK.md` are present; no secrets; only fictional data.
- Handoff in the PR (PROJECT / CHANGED / VERIFIED / DECISIONS / TODO / FILES). Claude reviews: ACCEPTED or REWORK.
